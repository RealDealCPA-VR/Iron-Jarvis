---
name: release-notes
description: >-
  Write release notes from a list of changes, in words a user understands.
---

Use this when the user is shipping a version and needs notes for users or a team.

1. Start from the real list of changes (commits, merged work, a changelog). Do not describe changes that are not in it.
2. Group them: New, Improved, Fixed, and Changes you must act on.
3. Write each line from the user's side: what they can now do or what no longer goes wrong. Leave out internal names.
4. Put anything that needs action (a setting, a migration, a breaking change) at the top, with the exact steps.
5. One line per change. Link or name the issue if the list gives one.
6. Say plainly what is known not to work yet.
7. Give the version and the date at the top.

The `shipping` package keeps its configuration in one global dict, `shipping.settings.CONFIG`, that every module reads (and that some modules change or depend on behind the scenes), so one program cannot use two sets of settings at the same time. Please remove the global: introduce an immutable `Settings` (a frozen dataclass) and pass it explicitly, as a keyword-only `settings=` argument, to every public function that needs configuration; `settings.load(path)` returns a `Settings` from a JSON file; `CONFIG` must no longer exist.

`REFACTOR.md` in the project says exactly what is expected — which functions take `settings`, what must stay the same, and what must become true — and `README.md` describes the package and its settings. Read both, and the whole package, before you start: some modules depend on the settings in ways that are easy to miss. In short: public function names and their other arguments stay the same; every result (return values, error messages, the command line's output) stays exactly the same; two calls with different `Settings` in the same process must not affect each other, in any order; and no module may keep configuration-dependent state between calls.

The tests use `CONFIG` today: update them to the new API, keeping every test file and every test, and make sure they all pass. Python 3.12, standard library only.

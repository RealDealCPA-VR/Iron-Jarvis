Bug report from finance: when the network drops a response from the payments server, `PaymentsClient.charge()` (in `billing/client.py`) raises `TransportTimeout` and the monthly invoice run in `invoices.py` stops. Make `charge()` retry — up to 3 attempts in total, as `billing/server_api.md` recommends — so that a lost response no longer stops the run. `test_charge_survives_a_lost_response` in `test_client.py` reproduces the report and fails today.

This is real money. Read `billing/server_api.md` and the documentation at the top of `invoices.py` before you change anything, and keep every promise they make: a customer must never be charged twice for one charge (also when a run that stopped is run again, as `invoices.py` describes), and a declined card must not be tried again. `FakeTransport` in `billing/transport.py` behaves like the real server, lost requests and lost responses included — use it to check your work.
